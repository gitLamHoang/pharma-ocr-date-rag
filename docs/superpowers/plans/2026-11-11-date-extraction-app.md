# Pharma Date Extraction App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the prototype in this repo with an app where a reviewer uploads a pharma PDF/scan and gets every date labeled by type, located on the page, consistency-checked, reviewable and exportable.

**Architecture:** Python FastAPI backend runs a 6-step pipeline (ingest → text+layout → rule candidates → Claude classification with verified AI-only additions → deterministic validation → SQLite store with frozen runs and append-only reviews). A React + TypeScript frontend (served by FastAPI in production) gives Documents and Review screens.

**Tech Stack:** Python 3.12, uv, FastAPI, Pydantic v2, anthropic SDK, pdfplumber, pypdfium2, pytesseract, Pillow, rapidfuzz, SQLite; React 18, TypeScript, Vite, TanStack Query, Vitest, Playwright; Docker Compose; gitleaks.

**Spec:** `docs/superpowers/specs/2026-11-11-date-extraction-app-design.md`

## Global Constraints

- Branch: `rebuild/refractor-ui-and-model`. Commit after every task with conventional-commit messages.
- **No secrets or sensitive data committed.** Keys only in git-ignored `.env`; commit `.env.example` with placeholders. `data/`, `*.sqlite*`, uploads, page images, logs git-ignored. Logs never print keys or document text. gitleaks runs in pre-commit and CI. Eval uses public documents only.
- Model: `claude-opus-5-5`, adaptive thinking, `output_config.effort = "medium"`, structured outputs via `output_config.format`, server-side refusal fallbacks (`fallbacks: "default"` with the beta `server-side-fallback-2026-07-01`). Forced `tool_choice` is not allowed on this model. Before writing Claude code, read the `claude-api` skill's `python/claude-api/README.md`; do not guess SDK calls.
- Provider by env: `CLAUDE_PROVIDER=anthropic|bedrock|vertex` (default `anthropic`); `AI_ENABLED=false` forces offline mode.
- Upload limits: PDF/PNG/JPG/TIFF, ≤ 50 MB, ≤ 100 pages. Page render 200 DPI. Claude page concurrency 4.
- AI-only verification: rules (or loose parser) must parse the verbatim text AND rapidfuzz `partial_ratio` ≥ 85 against that page's pdfplumber/Tesseract text.
- Tesseract packs: `eng+fra+deu+spa+vie+ara+rus+chi_sim+jpn` (use those installed; report missing ones in `/api/health`).
- Month-only dates: stored/displayed as `YYYY-MM`, compared as last day of month.
- Never: show a date not on the page; resolve an ambiguous numeric date without quoted evidence; invent a day for month-only dates; update/delete a review event.
- Palette (60/30/10): Midnight Navy `#1B2447`, Powder Blue `#C5D0EE`, Sunflower `#FFC93C` (accent only; never body text on light bg). No client branding. No AI-slop visuals (purple gradients, glass soup, emoji icons, filler copy).
- Design skills: art direction + final look pass with `taste-skill:design-taste-frontend` (app-screens run); build/critique/polish/harden with `impeccable:impeccable`.

## Review Focus

1. Corrupt, encrypted or zero-page PDF → document status `failed` with a readable message; server keeps running. (Task 3 + Task 8 tests)
2. Blank scan / page with no dates → run `done`, 0 dates, no flags, no error. (Task 4 test)
3. The same date string twice on one page (e.g. two signatures `12/03/2026`) → two distinct candidates with distinct boxes, not merged. (Task 4 test)
4. Claude returns an unknown candidate id, a type outside the taxonomy, or invalid JSON → that item ignored and logged, rule label kept, run still `done`. (Task 5 test)
5. Review submitted against a frozen (non-latest) run → HTTP 409, nothing written. (Task 7 + Task 9 tests)
